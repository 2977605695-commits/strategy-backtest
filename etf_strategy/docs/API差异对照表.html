价格类型14 = 限价, 11 = 市价, 5 = 最新价 (pricetype 参数)price=None → 市价；price=X → 限价；无独立价格类型枚举
下单数量必须为 100 的整数倍 (A 股)，手动取整必须为 100 的整数倍，系统自动取整或报错
订单回报异步回报，需通过 ContextInfo.callback 回调获取同步返回 Order 对象，含 order_id、filled、avg_fill_price

核心差异总结：QMT 的 pass_order 采用魔数编码，7 参数强类型，学习曲线陡峭但控制力强；PTrade 的 order 系列语义化程度更高，尤其 order_target_value 大幅简化调仓逻辑。迁移时需重点处理编码转换与数量取整逻辑差异。

四、注意事项

  1. QMT pass_order 的 pricetype 参数在不同券商版本中枚举值可能不同。部分券商版本中市价为 5 而非 11，需在部署前与券商确认枚举映射。
  2. PTrade handle_data 默认每分钟触发一次，若策略仅需日级别运行，必须用 context.bar_dt 或 scheduler.run_daily 做频率控制，否则会重复下单。
  3. QMT 行情数据在 handlebar 中通过 ContextInfo.get_market_data 获取时，历史 K 线的 count 参数受 set_universe 订阅范围限制，未订阅标的返回空值。
  4. PTrade get_bars 返回的日期字段是 date 而非 time，且 amount 字段名为 money，迁移时字段名映射必须逐项核对。
  5. 双平台 A 股下单数量必须为 100 的整数倍。QMT 不会自动取整，传入非整数倍数量会报错；PTrade 部分版本会自动向下取整但不保证一致性，建议统一在策略层做 int(vol / 100) * 100 处理。
  6. QMT ContextInfo.do_log 的日志级别用整数表示 (0=INFO, 1=WARN, 2=ERROR, 3=FATAL)，而非字符串。直接 print 的输出在服务端运行时不可见，必须用 do_log。
  7. PTrade context.portfolio.positions 仅返回当前持仓标的，已清仓标的不在字典中。若需查询历史持仓，需从 get_orders() 重建。
  8. 双平台 ETF 交易费率与最小变动价位与股票不同。ETF 最小变动单位为 0.001 元 (股票为 0.01 元)，下单价格精度需注意。部分 ETF 有涨跌幅限制 (±10%)，跨境 ETF 限制可能不同。
  9. QMT 断线重连后 ContextInfo 对象可能被重建，策略中不应将 ContextInfo 存入全局变量，应始终通过函数参数传递。
  10. PTrade 策略上传后编译发生在服务端，错误信息可能不够详细。建议在本地 Python 环境先做语法检查，注意 PTrade 的 Python 版本可能为 3.6，部分 3.8+ 语法 (如 walrus operator) 不可用。

五、迁移建议：从 QMT 迁到 PTrade

重写生命周期函数

将 init(ContextInfo) 改为 initialize(context)，handlebar(ContextInfo) 改为 handle_data(context, data)。全局变量存储方式从 ContextInfo.X = value 改为 context.X = value 或使用 g. 全局对象。

替换标的代码格式

编写 code_convert(code) 工具函数：将 .SH → .XSHG，.SZ → .XSHE。在 config.json 中统一存储一种格式，运行时按平台转换。批量替换 32 只 ETF 代码。

重写下单逻辑

将 pass_order(0, 1101, acc, code, 14, vol, price, ContextInfo) 替换为 order(code, vol, price=price)。调仓逻辑用 order_target_value(code, target_value) 替代手动计算差值。撤单逻辑从按标的撤单改为按 order_id 撤单。

适配行情与持仓接口

get_market_data → get_bars，注意字段名映射 (time→date, amount→money)。持仓接口从 get_stock_positions_in_account 改为 context.portfolio.positions，字段名从 m_nVolume 改为 total_amount 等。

验证与对齐

在 PTrade 模拟环境运行至少 5 个交易日，逐日对比 QMT 与 PTrade 的信号生成结果。重点关注：MA 计算数值是否一致、下单价格是否一致、持仓同步是否正确。偏差率应控制在 0.1% 以内。
